# Исполнение беклога операции

Навык исполняет беклог любой операции проекта. Порядок один на все операции
([BKL-006](${CLAUDE_PROJECT_DIR}/rules/operation-backlog-rules.md#признак-исполнения),
[BKL-007](${CLAUDE_PROJECT_DIR}/rules/operation-backlog-rules.md#стоп-знак-необратимой-задачи)) и остаётся
здесь единственным носителем: беклог порождает вход `backlog`, исполняет его
этот навык.

Этот файл — носитель порядка исполнения, и загружается он по адресу
`/backlog:backlog-run` перед первой задачей беклога: ссылкой норма названа,
но не подана, а беклог, исполненный без порядка, остаётся неотмеченным и несверенным
([BKL-008](${CLAUDE_PROJECT_DIR}/rules/operation-backlog-rules.md#передача-исполнения)). Порождённый беклог
несёт этот путь строкой-указателем, поэтому исполнение, начатое просьбой «исполни беклог»
без вызова навыка, до порядка тоже доходит.

## Границы навыка

Беклог навык не порождает и состав его задач не правит: порождение — дело входа, а правкой
считается только ход исполнения — отметки и значения, дописываемые во фронтматтер
([BKL-004](${CLAUDE_PROJECT_DIR}/rules/operation-backlog-rules.md#порождённое-не-правится)). Значения берутся
из фронтматтера и второй раз не собираются
([BKL-005](${CLAUDE_PROJECT_DIR}/rules/operation-backlog-rules.md#самодостаточность-значений)).

Обстоятельство, требующее другого состава задач, правит шаблон операции, а не лежащий беклог:
встретившееся однажды встретится снова. Правка шаблона действует на следующие операции,
и порождённый файл ею задним числом не меняется.

## Порядок исполнения

1. **Прочитать беклог** целиком: `<корень следа>/<операция>/<предмет>/tasks.md`. Адрес и предмет
   каждой операции — в [описании каталога беклогов](${CLAUDE_PROJECT_DIR}/backlog/README.md).
2. **Пройти задачи сверху вниз, по одной.** Для каждой:
   - сверить признак «выполнено ранее» с состоянием. Признак выполнен — задача пропускается,
     отметка ставится, исполнение идёт дальше;
   - исполнить задачу, если признак не выполнен;
   - проверить по строке проверки задачи;
   - отметить в беклоге: `- [ ]` → `- [x]`.
3. **Дописать добытые значения** во фронтматтер — подтверждения владельца и значения, рождённые
   задачами: беклог остаётся исполнимым в другом сеансе агента.
4. **Назвать владельцу итог** — что исполнено, что осталось ему, и путь беклога.

Прерванное исполнение продолжается с задачи, признак которой не выполнен: ни отката
исполненного, ни второго беклога возобновление не требует. Таблица версий беклога отметками
не пополняется — беклог исполняется, а не правится.

## Стоп-знак

Задача со стоп-знаком исполняется только после отдельного подтверждения владельца, запрошенного
непосредственно перед ней
([BKL-007](${CLAUDE_PROJECT_DIR}/rules/operation-backlog-rules.md#стоп-знак-необратимой-задачи)).
Запрос показывает то, что названо в тексте задачи, и называет последствия прямо: что изменится,
в каком объёме и возможен ли возврат.

Подтверждение, данное заранее, подтверждением не является: значения необратимой задачи на момент
утверждения беклога могут не существовать — они рождаются предшествующими задачами.

Отказ владельца исполнение прекращает: задачи не отменяются и не переписываются, беклог остаётся
пригодным к продолжению. Задача со стоп-знаком не обходится — беклог линеен, и последующие задачи
при отказе не исполняются.

## Исходы задач

| Исход задачи | Что делать |
|--------------|------------|
| Проверка задачи сошлась | Отметить задачу, дописать добытые значения во фронтматтер, перейти к следующей |
| Признак «выполнено ранее» выполнен, а отметки нет | Верно состояние: отметить и идти дальше |
| Отметка стоит, а признак не выполнен | Верно состояние: исполнить задачу заново |
| Отказ прогона с перечнем препятствий | Показать препятствия как есть и остановиться: исправление называет владелец |
| Отказ владельца перед задачей со стоп-знаком | Прекратить исполнение, беклог оставить пригодным к продолжению |
| Задача хостовой части | Передать владельцу перечнем команд и отметить: средств виртуализации в контейнере нет |
