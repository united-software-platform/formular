# Беклоги операций

Каталог порождённых беклогов: по каталогу на операцию, внутри — по каталогу на предмет,
в каждом `tasks.md` с порядком работ и следом исполнения.

## Что здесь лежит

Путь беклога складывается из имени операции и её предмета: `<операция>/<предмет>/tasks.md`.
Предмет операции, повторяемой над одним и тем же предметом предметной области, — штамп прогона
`YYYYMMDDHHMMSS`: повторный прогон получает свой беклог, а не упирается в занятый адрес. Предмет
операции, выполнимой над своим предметом однажды, — предмет предметной области: второго порядка
работ у неё не бывает.

```text
backlog/
  sample-operation/<штамп>/tasks.md     образцовая операция
```

Корень этого каталога — умолчание входа, а не константа кода: вызов принимает `--root`, и каталог
следа принадлежит тому, кто продукт применяет. Сами беклоги в репозиторий не попадают — закрыты
`.gitignore`; этот документ оставлен исключением, потому что отвечает на вопрос об адресе,
а не хранит чей-то прогон.

Фронтматтер несёт значения исполнения — второй раз они не собираются. Дальше идут группы задач,
у каждой задачи проверка и признак «выполнено ранее». Необратимую задачу открывает стоп-знак:
она исполняется только после отдельного подтверждения владельца.

Беклог остаётся на своём пути и после исполнения: он отвечает на вопрос, как прошёл конкретный
прогон.

## Каким операциям нужен беклог

Тем, у которых есть необратимый шаг либо шаг, выполнимый только владельцем
([BKL-001](../rules/operation-backlog-rules.md#беклог-как-носитель-порядка)). Прочим операциям
носитель порядка для одного вызова превращается в обёртку.

## Откуда берётся

Беклог порождается входом, а руками не пишется
([BKL-003](../rules/operation-backlog-rules.md#порождение-прогоном)):

```bash
backlog generate --operation sample-operation \
  --value target=проба --flag host-part
```

Предмет называется ключом `--subject`; без него предметом становится штамп прогона. Признаки
условных блоков называются полностью — и взведённые `--flag`, и снятые `--no-flag`: признак,
не названный вовсе, оставляет маркер блока в тексте и прекращает порождение.

Состав вызова целиком — `backlog generate --help`. Вход поставляется плагином `backlog`,
и имя команды не зависит от того, куда плагин установлен. Исполняет беклог навык
`/backlog:backlog-run` — он же носитель порядка исполнения.

## Порождённое не правится

Беклог, порождённый прежним прогоном, задним числом не правится — ни по составу задач, ни
по вызовам, которые он называет
([BKL-004](../rules/operation-backlog-rules.md#порождённое-не-правится)). Поэтому в исполненных
беклогах остаются имена снятых инструментов: они фиксируют, чем операция была исполнена, а не
чем её исполнить сегодня. Текущий способ вызова называет этот документ.
