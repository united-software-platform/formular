# Приведение состава группы {{group}}

Беклог процесса приведения состава группы: путь от утверждения «состав такой» до приведённого
размещения. Состав группы — решение владельца, и процесс его исполняет, а не выбирает. Значения
процесса несёт фронтматтер — второй раз они не собираются. Задачи исполняются по порядку.

Порядок исполнения — отметки задач, выводимый признак «выполнено ранее», стоп-знак перед
необратимой задачей — задан [WSO-019](../../../rules/workspace-operations-rules.md#необратимость),
и его носитель — `.claude/skills/workspace-backlog/SKILL.md`: прочитать его перед первой
задачей; здесь он не пересказывается.

## 2. Состав группы в реестре

{{#composed}}
- [ ] 2.1 Приписать группу названным записям — по вызову на запись:

  ```bash
  bash tools/host-runner/call.sh edit-entry NAME=<имя> GROUP={{group}}
  ```

  Записи состава: `{{names_listed}}`

  - Проверка: у каждой названной записи `projects.yaml` фасет `group` равен `{{group}}`
  - Выполнено ранее: фасет `group` уже равен `{{group}}` — правка значением, совпадающим
    с лежащим в реестре, запись не меняет и исход «не изменилась» отказом не является
{{/composed}}
{{^composed}}
- [ ] 2.1 Приписывать группу нечему: состав пуст — это роспуск группы
  - Проверка: перечень состава во фронтматтере пуст
  - Выполнено ранее: проверка состояния — повторяется без последствий
{{/^composed}}
- [ ] 2.2 Снять группу у записей, которым она приписана и которых в составе нет:

  ```bash
  grep -B6 "group: {{group}}" projects.yaml | grep "name:"
  bash tools/host-runner/call.sh edit-entry NAME=<имя> GROUP=null
  ```

  Правка реестра на этом заканчивается, поэтому обязательный прогон проверки состава
  по [REG-011](../../../rules/project-registry-rules.md#проверка-реестра) входит в проверку
  этой задачи: `bash tools/host-runner/call.sh registry-lint`.

  - Проверка: записей с фасетом `group`, равным `{{group}}`, и вне перечня состава
    в `projects.yaml` не осталось; проверка моделей даёт код возврата `0`
  - Выполнено ранее: таких записей нет

## 3. Размещение

- [ ] 3.1 Породить миграцию размещения по записям, чей путь разошёлся с целевым:

  ```bash
  bash tools/host-runner/call.sh move-project NAME=<имена через запятую>
  ```

  Миграция одна на весь состав, и беклог наката она порождает один. Записи, уже лежащие
  по целевым путям, операций не дают и порождение не прекращают. Записать версию миграции
  во фронтматтер в `migration_version`, перечень «откуда куда» — в `placements`.

  - Проверка: `exit: 0`, в каталоге `layout/` лежит неприменённая миграция, называющая эти
    записи, и порождён беклог её наката
  - Выполнено ранее: версия числится во фронтматтере, а файл миграции лежит в `layout/`
  - Исход «ни одна названная запись места не меняет» отказом процесса не является: размещение
    уже приведено, и задача 3.2 выполнена ранее
- [ ] 3.2 Накатить миграцию по порождённому беклогу размещения
  `backlog/move-project/<версия>/tasks.md`. Стоп-знак стоит там, и подтверждение
  запрашивается непосредственно перед накатом — второго подтверждения этот беклог
  не запрашивает
  - Проверка: версия числится в `layout/applied.yaml`, пути записей равны целевым, каталоги
    по этим путям существуют
  - Выполнено ранее: версия есть в `layout/applied.yaml` и каталоги лежат по целевым путям

## 4. Завершение

- [ ] 4.1 Пометить значение словаря устаревшим, если состав группы пуст:

  ```bash
  bash tools/host-runner/call.sh deprecate-value SECTION=groups ID={{group}} REPLACED_BY=null
  ```

  - Проверка: при пустом составе значение `{{group}}` несёт `deprecated: true`; при непустом
    составе задача не исполняется
  - Выполнено ранее: состав непуст либо значение уже помечено устаревшим
- [ ] 4.2 Передать владельцу перечень внешних ссылок к правке — клоны репозиториев, настройки
  среды разработки, локальные скрипты — и напомнить об опустевшем каталоге: накат каталогов
  не удаляет, и каталог прежнего размещения остаётся в дереве. Сканирование пространства
  показывает его мусором: `sh tools/workspace/ws.sh scan-workspace`
  - Проверка: перечень размещений из фронтматтера — поле `placements` — сообщён владельцу
    вместе с напоминанием о каталоге; правку и уборку он выполняет сам
  - Выполнено ранее: перечень сообщён владельцу в этом сеансе
