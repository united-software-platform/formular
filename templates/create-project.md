# Первичное размещение проекта {{project}}

Беклог операции первичного размещения: путь от заведённой записи до заведённого каталога.

Запись реестра к этому моменту уже дописана с путём `null`, а целевой путь живёт в операции
порождённой миграции: единственный носитель раскладки — миграция, и путь записи приводит накат.

Значения операции несёт фронтматтер — второй раз они не собираются
([BKL-005]({{rules}}#самодостаточность-значений)). Задачи исполняются
по порядку.

Порядок исполнения — отметки задач, выводимый признак «выполнено ранее», стоп-знак перед
необратимой задачей — задан [BKL-006]({{rules}}#признак-исполнения)
и [BKL-007]({{rules}}#стоп-знак-необратимой-задачи), а его носитель —
`{{runner}}`: прочитать его перед первой задачей; здесь он
не пересказывается ([BKL-008]({{rules}}#передача-исполнения)). Указатель носителя несёт
и фронтматтер значением `runner`: оттуда его читает проверка, отсюда — исполнитель.

## 2. Накат размещения

- [ ] 2.1 **Стоп-знак.** Показать владельцу версию миграции `{{version}}`, целевой путь
  `{{target}}` и то, что накат заводит каталог пустым: содержимое проекта он не создаёт.
  Назвать и необратимость для внешних ссылок — заведённый путь попадёт в клоны, настройки
  среды разработки и локальные скрипты. Дождаться подтверждения, записать его во фронтматтер
  в `confirmed.apply` и накатить:

  ```bash
  bash tools/host-runner/call.sh layout-apply VERSION={{version}}
  ```

  - Проверка: `exit: 0`, пустой каталог лежит по пути `{{target}}`, поле `path` записи
    `{{project}}` равно `{{target}}`, версия `{{version}}` числится в `layout/applied.yaml`,
    а журнал операций несёт событие `MigrationApplied`
  - Выполнено ранее: версия `{{version}}` есть в `layout/applied.yaml` и каталог лежит
    по пути `{{target}}`
- [ ] 2.2 Прогнать проверку моделей после наката:
  `bash tools/host-runner/call.sh registry-lint`
  - Проверка: код возврата `0`: путь записи приведён и каталог по нему существует
  - Выполнено ранее: проверка состояния — повторяется без последствий
