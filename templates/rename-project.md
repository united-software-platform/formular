# Переименование проекта {{previous}} → {{project}}

Беклог операции переименования: путь от переименованной записи до каталога, лежащего по пути
нового имени. Имя записи правит порождающий прогон, каталог — накат: эти два состояния
разведены во времени, и беклог ведёт от первого ко второму. Значения операции несёт
фронтматтер — второй раз они не собираются.

Границу операции держит её состав: удалённый репозиторий, настройка `origin`, имена сервисов
и переменные окружения внутри каталога проекта командой не правятся — они передаются владельцу
перечнем команд последней задачей.

Порядок исполнения — отметки задач, выводимый признак «выполнено ранее», стоп-знак перед
необратимой задачей — задан [WSO-019](../../../rules/workspace-operations-rules.md#необратимость),
и его носитель — `.claude/skills/workspace-backlog/SKILL.md`: прочитать его перед первой
задачей; здесь он не пересказывается.

- [ ] 1.1 Прочитать файл миграции целиком:
  `layout/Version{{version}}_*.yaml`
  - Проверка: файл содержит одну операцию размещения — `{{project}}`: `{{source}}` → `{{target}}`
  - Выполнено ранее: проверка состояния — повторяется без последствий
- [ ] 1.2 Прогнать проверку моделей пространства:
  `bash tools/host-runner/call.sh registry-lint`
  - Проверка: код возврата `0`; запись `{{project}}` есть в `projects.yaml`, записи
    `{{previous}}` в нём нет
  - Выполнено ранее: проверка состояния — повторяется без последствий
- [ ] 1.3 Убедиться, что каталог лежит по исходному пути, а целевой путь свободен
  - Проверка: каталог `{{source}}` существует, `{{target}}` не существует
  - Выполнено ранее: каталог лежит по пути `{{target}}` — накат уже состоялся

## 2. Остановка окружения

- [ ] 2.1 Остановить окружение проекта перед накатом: работающий контейнер держит привязку
  к прежнему пути `{{source}}`, и после наката сервисы работают с каталогом, которого больше
  нет. Условие лежит в тексте задачи: есть файл описания сервисов в каталоге проекта — сервисы
  останавливаются, нет — задача отмечается неприменимой.

  Средств виртуализации в контейнере агента нет, поэтому команду исполняет владелец на хосте,
  а агент её передаёт:

  ```bash
  docker compose -f {{source}}/docker-compose.yaml down
  ```

  Команда с удалением томов здесь не называется и не исполняется: она превращает остановку
  в потерю данных.

  - Проверка: сервисы проекта не запущены; тома не удалялись
  - Выполнено ранее: сервисы проекта не запущены
- [ ] 2.2 Назвать владельцу, что данные остаются в томах прежнего имени: для средств запуска
  окружения имя `{{previous}}` и имя `{{project}}` суть разные проекты, и перенос данных между
  их томами — работа владельца
  - Проверка: владельцу названы прежнее имя `{{previous}}` и новое `{{project}}`; тома
    не удаляются и не переносятся агентом
  - Выполнено ранее: названо владельцу в этом сеансе

## 3. Накат переименования

- [ ] 3.1 **Стоп-знак.** Показать владельцу версию миграции `{{version}}`, пару путей
  `{{source}}` → `{{target}}` и то, что перенос необратим для внешних ссылок — клонов,
  настроек среды разработки, локальных скриптов. Дождаться подтверждения, записать его
  во фронтматтер в `confirmed.apply` и накатить:

  ```bash
  bash tools/host-runner/call.sh layout-apply VERSION={{version}}
  ```

  - Проверка: `exit: 0`, каталог лежит по пути `{{target}}`, поле `path` записи `{{project}}`
    равно `{{target}}`, версия `{{version}}` числится в `layout/applied.yaml`, а журнал
    операций несёт событие `MigrationApplied`
  - Выполнено ранее: версия `{{version}}` есть в `layout/applied.yaml` и каталог лежит
    по пути `{{target}}`
- [ ] 3.2 Прогнать проверку моделей после наката:
  `bash tools/host-runner/call.sh registry-lint`
  - Проверка: код возврата `0`: путь записи приведён и каталог по нему существует
  - Выполнено ранее: проверка состояния — повторяется без последствий

## 4. Внешние ссылки и хостовые шаги

- [ ] 4.1 Назвать владельцу, что версии миграций, предшествующие этому переименованию,
  повторному накату и возврату не подлежат: они называют запись прежним именем `{{previous}}`,
  а их файлы правке не подлежат, и накат отказывает на разрешении имени
  - Проверка: владельцу названы прежнее имя и версия `{{version}}`, связывающая его с новым
    в журнале операций
  - Выполнено ранее: названо владельцу в этом сеансе
- [ ] 4.2 Передать владельцу перечнем команд хостовые шаги: переименование удалённого
  репозитория и правка настройки `origin`. Агент их не исполняет — правка лежит внутри
  каталога проекта, а он команде не принадлежит

  ```bash
  gh repo rename {{project}} --repo <пространство имён>/{{previous}}
  git -C {{target}} remote set-url origin <новый адрес>
  ```

  - Проверка: перечень сообщён владельцу; ни одна из команд агентом не исполнена
  - Выполнено ранее: перечень сообщён владельцу в этом сеансе
- [ ] 4.3 Назвать владельцу итог и границу: запись переименована, каталог приведён, событие
  в журнале. Окружение остаётся остановленным — подъём его и правка префикса имён сервисов
  в файлах проекта остаются работой владельца
  - Проверка: итог сообщён, незавершённых задач агента не осталось
  - Выполнено ранее: итог сообщён в этом сеансе
