# Перемещение проектов {{project}}

Беклог операции перемещения: путь от порождённой миграции до приведённых каталогов. Беклог один
на всю миграцию, сколько бы записей она ни называла: необратимый шаг здесь один. Значения операции
несёт фронтматтер — второй раз они не собираются. Задачи исполняются по порядку.

Порядок исполнения — отметки задач, выводимый признак «выполнено ранее», стоп-знак перед
необратимой задачей — задан [WSO-019](../../../rules/workspace-operations-rules.md#необратимость),
и его носитель — `.claude/skills/workspace-backlog/SKILL.md`: прочитать его перед первой
задачей; здесь он не пересказывается.

## 2. Остановка окружения

- [ ] 2.1 Остановить окружение каждого проекта, каталог которого переносит накат: работающий
  контейнер держит привязку к прежнему пути, и после наката сервисы работают с каталогом,
  которого больше нет. Условие лежит в тексте задачи: есть файл описания сервисов в каталоге
  проекта — сервисы останавливаются, нет — задача отмечается неприменимой.

  Средств виртуализации в контейнере агента нет, поэтому команду исполняет владелец на хосте,
  а агент её передаёт — по каталогу на проект:

  ```bash
  docker compose -f <каталог проекта>/docker-compose.yaml down
  ```

  Команда с удалением томов здесь не называется и не исполняется: она превращает остановку
  в потерю данных. Парного подъёма задача не несёт: окружение поднимает владелец, когда
  сочтёт нужным.

  - Проверка: сервисы проектов `{{project}}` не запущены; тома не удалялись
  - Выполнено ранее: сервисы переносимых проектов не запущены

## 3. Накат перемещения

- [ ] 3.1 **Стоп-знак.** Показать владельцу версию миграции `{{version}}`, перечень путей
  `{{placements}}` и то, что перенос необратим для внешних ссылок — клонов, настроек среды
  разработки, локальных скриптов. Подтверждение одно на всю миграцию: необратимый шаг здесь
  один. Дождаться его, записать во фронтматтер в `confirmed.apply` и накатить:

  ```bash
  bash tools/host-runner/call.sh layout-apply VERSION={{version}}
  ```

  - Проверка: `exit: 0`, каждый каталог лежит по своему целевому пути, поле `path` каждой
    записи равно ему, версия `{{version}}` числится в `layout/applied.yaml`, а журнал
    операций несёт событие `ProjectMoved`
  - Выполнено ранее: версия `{{version}}` есть в `layout/applied.yaml` и каталоги лежат
    по целевым путям
- [ ] 3.2 Прогнать проверку моделей после наката:
  `bash tools/host-runner/call.sh registry-lint`
  - Проверка: код возврата `0`: пути записей приведены и каталоги по ним существуют
  - Выполнено ранее: проверка состояния — повторяется без последствий
