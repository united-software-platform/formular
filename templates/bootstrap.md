# Подъём проекта {{name}}

Беклог подъёма: путь от записи реестра до рабочего репозитория.

Значения операции несёт фронтматтер — второй раз они не собираются
(BKL-005; текст нормы — `backlog norms --rule BKL-005`). Задачи исполняются
по порядку.

Порядок исполнения — отметки задач, выводимый признак «выполнено ранее», стоп-знак перед
необратимой задачей — задан BKL-006 (`backlog norms --rule BKL-006`)
и BKL-007 (`backlog norms --rule BKL-007`), а его носитель —
`{{runner}}`: прочитать его перед первой задачей; здесь он
не пересказывается (BKL-008; текст нормы — `backlog norms --rule BKL-008`). Указатель носителя несёт
и фронтматтер значением `runner`: оттуда его читает проверка, отсюда — исполнитель.

## 3. Накат каталога

Накат исполняется по беклогу первичного размещения, порождённому задачей 2.1:
`backlog/create-project/<migration_version>/tasks.md`. Его задачи здесь не повторяются —
у порядка наката один носитель, и второй разошёлся бы с ним при первой же правке шаблона.

- [ ] 3.1 **Стоп-знак.** Накат необратим, и подтверждение владельца запрашивается один раз —
  задачей беклога размещения, непосредственно перед накатом. Исполнить этот беклог целиком:
  его стоп-знак называет версию из `migration_version`, целевой путь из `project_path`
  и команду наката, а завершающие задачи передают заведённый путь владельцу
  - Проверка: `exit: 0` у наката, каталог по пути `project_path` существует, поле `path` записи
    непусто, версия числится в `layout/applied.yaml`, а задачи беклога размещения отмечены
  - Выполнено ранее: версия из `migration_version` есть в `layout/applied.yaml`, поле `path`
    записи непусто и каталог по нему существует — беклог размещения пройден по признакам
    своих задач, и повторный проход по нему пространство не меняет
