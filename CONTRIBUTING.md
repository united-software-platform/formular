## Устройство репозитория

Поставка — каталог плагина [`plugin/backlog/`](./plugin/backlog):

| Что | Где в поставке |
|-----|----------------|
| Манифест плагина — носитель бейджа версии | [`.claude-plugin/plugin.json`](./plugin/backlog/.claude-plugin/plugin.json) |
| Вход командной строки | [`bin/backlog`](./plugin/backlog/bin/backlog) |
| Домен, сценарии и адаптеры | [`src/backlog/`](./plugin/backlog/src/backlog) |
| Сборка окружения | [`lib/python-env.sh`](./plugin/backlog/lib/python-env.sh) |
| Порядок исполнения | [`skills/backlog-run/`](./plugin/backlog/skills/backlog-run/SKILL.md) |
| Приёмка шаблона | [`skills/backlog-template/`](./plugin/backlog/skills/backlog-template/SKILL.md) |
| Порождение навыком | [`skills/backlog-generate/`](./plugin/backlog/skills/backlog-generate/SKILL.md) |
| Образцовый шаблон | [`templates/`](./plugin/backlog/templates) |
| Нормы беклога и глоссарий | [`share/`](./plugin/backlog/share) |

Принадлежность репозитория, в поставку не входящая:

| Что | Где |
|-----|-----|
| Точка входа агентов — единственная | [`AGENTS.md`](./AGENTS.md) |
| Запись источника плагина — маркетплейс `formular` | [`.claude-plugin/marketplace.json`](./.claude-plugin/marketplace.json) |
| Проверки ядра и входа | [`tests/`](./tests) |
| Общие правила разработки — копии поставки tessera; секцию в `AGENTS.md` ведёт скрипт поставки | [`.tessera/rules/`](./.tessera/rules) |
| Закрепление openspec CLI | [`mise.toml`](./mise.toml) |
| Спецификации и изменения OpenSpec | [`openspec/`](./openspec) |
| Образец плагина агента — экспортируемая спецификация архитектуры | [`docs/spec/agent-plugin-blueprint/`](./docs/spec/agent-plugin-blueprint/index.md) |
| Исследование способов поставки | [`docs/research/import-into-other-projects.md`](./docs/research/import-into-other-projects.md) |
| Документ кейсов | [`docs/use-cases.md`](./docs/use-cases.md) |
| Каталог следа — порождённые беклоги, закрытый `.gitignore` | `backlog/` |
| Текст лицензии — носитель бейджа лицензии | [`LICENSE`](./LICENSE) |

Ядру зависимостей не нужно — оно обходится стандартной библиотекой. Механизм сборки окружения
для зависимостей в поставке всё же есть: [`lib/python-env.sh`](./plugin/backlog/lib/python-env.sh)
собирает окружение интерпретатора, когда инструменту поставки зависимость потребуется.

Каталоги регистрации харнесов `.agents/`, `.claude/` и `.zcode/` — локальные: их создаёт каждый
разработчик под свои инструменты, в индексе git их нет.

## Локальная настройка

Порядок и предупреждения — в разделе «Локальная настройка»
[`AGENTS.md`](./AGENTS.md#локальная-настройка); здесь — сами шаги.

1. Инструментарий: `mise install` ставит openspec CLI версии, закреплённой в `mise.toml`;
   интерпретатор python приходит каскадом workspace. При первом входе в каталог mise предлагает
   доверять `mise.toml` проекта.

2. Навыки и правила tessera — из корня репозитория, профилем без formular: плагин `backlog`
   в этом репозитории свой.

   ```bash
   curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --project --profile tessera
   ```

3. Плагин `backlog` — маркетплейс `formular` добавляется каталогом клона.

4. Инструментация OpenSpec — под харнесы разработчика:

   ```bash
   openspec init --tools <харнесы> --language ru --scope project
   ```

## Правка поставки

Нормы и определения понятий существуют в одном экземпляре — в
[`plugin/backlog/share/`](./plugin/backlog/share), образцовый шаблон — в
[`plugin/backlog/templates/`](./plugin/backlog/templates). Копий в дереве репозитория нет:
[`AGENTS.md`](./AGENTS.md) подключает
[нормы](./plugin/backlog/share/rules/operation-backlog-rules.md)
и [глоссарий](./plugin/backlog/share/docs/glossary.md) прямо из источника, и правка видна
контексту репозитория без установочного прогона.

Источником плагина [`.claude-plugin/marketplace.json`](./.claude-plugin/marketplace.json)
объявлен каталог `./plugin/backlog` этого же репозитория: плагин грузится из него на месте,
а не установкой самого себя, поэтому правка механизма доезжает до следующего сеанса без
публикации и без смены версии.

Шаблоны операций любого проекта-потребителя называют нормы кодом и вызовом
`backlog norms --rule BKL-NNN`, а не ссылкой на файл.

Общие правила разработки правятся в репозитории tessera. Копии в
[`.tessera/rules/`](./.tessera/rules) дословные: правленая вручную копия останавливает
установку, а обновление — повторный запуск скрипта поставки из корня репозитория.

## Образец плагина агента

[`docs/spec/agent-plugin-blueprint/`](./docs/spec/agent-plugin-blueprint/index.md) — архитектура
`backlog`, описанная как переносимое техническое решение. Другой проект строит по ней свой плагин
со своим предметом. `backlog` в ней — эталонная реализация: на него ссылаются по путям,
но требования из него не выводятся.

### Когда править спецификацию

Изменение плагина сверяется с решениями `APB-001`..`APB-012`, если оно затрагивает хотя бы одно:
поставку, вход, зависимости, слои и контракты ядра, нормы поставки, навыки, конвейер артефакта,
приёмку шаблона, адресацию или проверки.

| Что изменилось | Что править |
|----------------|-------------|
| Изменение укладывается в действующее решение | Ничего, кроме путей и имён в [эталонной реализации](./docs/spec/agent-plugin-blueprint/reference-implementation.md), если они поменялись |
| Изменение меняет решение | Запись решения в [`decisions.md`](./docs/spec/agent-plugin-blueprint/decisions.md) и связанные с ней строки [чек-листа](./docs/spec/agent-plugin-blueprint/conformance.md) |
| Эталон начал отступать от правила | Новая запись `APB-DNN` в [`deviations.md`](./docs/spec/agent-plugin-blueprint/deviations.md) |
| Отклонение эталона устранено | Статус записи `APB-DNN` и упоминание в воплощении соответствующего решения |

Пять отклонений `APB-D01`..`APB-D05` открыты: эталон пока отступает от CLAR и CQRS. Это готовые
задачи на выравнивание эталона по правилам.

У каждого файла спецификации своя таблица версий. Заголовки решений `APB-NNN` служат якорями
ссылок из чек-листа, отклонений и `README.md`, поэтому при правке заголовка нужно сверить ссылки.
Отдельной проверки ссылок в репозитории нет.

### Перенос в другой проект

1. Проверить, что в целевом проекте стоят навыки и правила tessera: спецификация ссылается
   на их коды и сама их не несёт.
2. Скопировать каталог `docs/spec/agent-plugin-blueprint/` в целевой проект по тому же пути,
   иначе относительные ссылки на `.tessera/rules/` не разрешатся.
3. Поручить агенту пройти [чек-лист соответствия](./docs/spec/agent-plugin-blueprint/conformance.md)
   и выдать отчёт в его форме. По ходу проверки агент ничего не исправляет.
4. Исправления по отчёту вести отдельными задачами целевого проекта, в порядке решений
   от `APB-001` к `APB-012`.

> **Внимание:** перенесённая спецификация — снимок, а не установленная копия. Ни механизма
> обновления, ни манифеста у неё нет. Перенесённую версию называет последняя строка таблицы
> версий `index.md`, и правка образца здесь до целевого проекта сама не доходит.

## Блок бейджей

Блок стоит в [`README.md`](./README.md) между заголовком и назначением.

| Бейдж | Источник значения | Режим | Цель ссылки |
|-------|-------------------|-------|-------------|
| Версия плагина `backlog` | Манифест `plugin/backlog/.claude-plugin/plugin.json` — raw-файл на ветке `main` | Динамический — shields `dynamic/json`, поле `version` | Страница манифеста в репозитории |
| Лицензия MIT | Неизменная характеристика, носителя нет | Статический | Текст лицензии MIT в реестре SPDX |

Бейджи читают ветку `main` GitHub: несопровождённая ветка или локальные правки в бейдж
не попадают. Переименование манифеста или смена пути сломает динамический бейдж — носители
значений перечислены в таблице.

## Проверки

Проверки прогоняются до отправки изменений, каждая — одной командой:

```bash
python3 -m unittest discover -s tests         # ядро и вход
backlog check-template <шаблон>               # приёмка шаблона операции — при правке шаблона
openspec validate <имя изменения> --strict    # артефакты изменения OpenSpec
```

Имя `backlog` известно внутри сеанса харнеса с включённым плагином; вне сеанса вызывается
`plugin/backlog/bin/backlog`. Приёмка шаблона обязательна при правке шаблона по
[BKL-009](./plugin/backlog/share/rules/operation-backlog-rules.md#прогон-при-правке-шаблона).
Полный состав вызова команды печатает `<команда> --help`.

## Правила и процесс

| Вопрос | Норма |
|--------|-------|
| Как озаглавлен и чем наполнен коммит | [GIT-009](./.tessera/rules/git-rules.md#формат-сообщения-коммита) |
| Откуда берутся код, номер и описание задачи | [GIT-010](./.tessera/rules/git-rules.md#формат-сообщения-коммита) |
| Когда коммитить и отправлять изменения | [GIT-015](./.tessera/rules/git-rules.md#коммиты-и-push) |
| Можно ли дописать подпись агента | [GIT-012](./.tessera/rules/git-rules.md#запрет-служебных-подписей) |
| Что делать с незакоммиченными правками в файле | [GIT-020](./.tessera/rules/git-rules.md#гейт-редактирования) |
| Чем завершается каждый документ | [DOC-022](./.tessera/rules/documentation-rules.md#жизненный-цикл-документа) |
| Какой материал в каком документе | [DGN-001](./.tessera/rules/project-docs-rules.md#роли-читателей-dgn-001) |

Единая точка входа агентов — [`AGENTS.md`](./AGENTS.md): понятия и нормы предмета подключаются
из поставки, общие правила разработки перечислены секцией tessera. Имя рабочей ветки строится
по шаблону `{CODE}-NNN-{краткое-описание}` с кодом проекта `FRM`; шаблон называет раздел
«Процесс разработки» [`AGENTS.md`](./AGENTS.md#процесс-разработки).

Работа ведётся изменениями OpenSpec в три шага:

1. **Предложение** — предложение, решения и задачи изменения: `openspec new change <имя>`,
   затем инструкции по артефактам — `openspec instructions <артефакт> --change <имя>`.
2. **Исполнение** — задачи проходятся по порядку: `openspec instructions apply --change <имя>`.
3. **Архивация** — `openspec archive <имя>`: состоявшееся изменение уходит в архив,
   а спецификация принимает его дельту.

В харнесе с инструментацией OpenSpec те же шаги доступны навыками `/openspec-propose`,
`/openspec-apply-change` и `/openspec-archive-change`.

Предмет системы описан спецификациями
[`openspec/specs/backlog/`](./openspec/specs/backlog/operation-backlog/spec.md). Каталог
`openspec/changes/archive/` чтению не подлежит —
[READ-004](./.tessera/rules/reading-rules.md#запрет-каталогов-read-004).
