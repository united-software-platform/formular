# formular

Система порождения и исполнения беклогов операций для Claude Code. Беклог нужен операции,
в которой есть необратимый шаг либо шаг, выполнимый только вами: порядок задач лежит в файле,
агент исполняет его по шагам, спрашивает вас перед необратимым и продолжает с места после обрыва.

## Что нужно

- Claude Code;
- `python3` с модулем `venv` — других зависимостей нет.

> **Внимание:** в claude.ai и Cowork система не работает: там нет команды `backlog`.

Дальше все шаги показаны на примере операции `release` — выпуск версии.

---

## Шаг 1. Установка

Из любой оболочки, где есть `claude`:

```bash
claude plugin marketplace add united-software-platform/formular
claude plugin install backlog@formular
```

Файлов в проекте установка не создаёт.

Проверка — в сеансе Claude Code попросите агента выполнить `backlog norms --rule BKL-001`:
команда печатает первое правило.

> **Важно:** имя `backlog` известно только внутри сеанса Claude Code — команды из шагов ниже
> выполняет агент. В обычном терминале `backlog: команда не найдена` — это не ошибка установки,
> см. [кейс 13](./docs/use-cases.md#кейс-13-разобраться-почему-вход-не-зовётся).

Подробнее — [кейс 2](./docs/use-cases.md#кейс-2-поставить-механизм-в-свой-проект).

## Шаг 2. Создать шаблон

Шаблон описывает задачи операции. Это файл `templates/<операция>.md`, и имя файла — имя операции:
`templates/release.md` создаёт операцию `release`.

**В сеансе Claude Code** вызовите навык и опишите операцию:

```text
/backlog:backlog-template заведи операцию release: выпуск версии, необратимый шаг — публикация тега
```

Агент проверит, нужен ли операции беклог, напишет шаблон и примет его проверкой.

**Вручную** — возьмите образец и переделайте под себя:

```bash
mkdir -p templates
backlog sample > templates/release.md
```

В образце поменяйте:

1. Задачи — на задачи своей операции. Каждая задача несёт строку `Проверка:` и строку
   `Выполнено ранее:` — как узнать, что задача уже сделана.
2. Значения — на свои: во фронтматтере `version: {{version_scalar}}`, в тексте задач
   `{{version}}`; заполнятся из вызова в шаге 3.
3. Необратимую задачу — откройте словом **Стоп-знак** и опишите последствия.
4. Условный блок `{{#host-part}}` — на свой, например `{{#publish-tag}}`, либо удалите.

Первые две задачи образца и абзацы с кодами `BKL-005`..`BKL-008` оставьте как есть: это каркас,
его требует проверка.

Затем проверьте шаблон — до кода возврата `0`:

```bash
backlog check-template templates/release.md
```

Подробнее — [кейс 4](./docs/use-cases.md#кейс-4-написать-шаблон-своей-операции)
и [кейс 5](./docs/use-cases.md#кейс-5-создать-и-принять-шаблон-из-внешней-системы).

## Шаг 3. Породить беклог

Беклог — шаблон, заполненный значениями конкретного запуска:

```bash
backlog generate --operation release --subject v1.4.0 \
  --value version=1.4.0 --flag publish-tag
```

- `--operation` — имя шаблона;
- `--subject` — что выпускаем; без него подставится время запуска;
- `--value` — значения шаблона, по одному на ключ;
- `--flag` / `--no-flag` — включить или выключить условный блок шаблона. Называются **все**
  блоки шаблона, иначе порождение остановится.

Результат — файл `backlog/release/v1.4.0/tasks.md`. Уже лежащий беклог не перезаписывается:
чтобы начать заново, назовите другой `--subject`.

Если порождённые беклоги не коммитятся, добавьте в `.gitignore` строку `backlog/*`.

Подробнее — [кейс 6](./docs/use-cases.md#кейс-6-породить-беклог-своей-операции).

## Шаг 4. Запустить исполнение

В сеансе Claude Code:

```text
/backlog:backlog-run исполни backlog/release/v1.4.0/tasks.md
```

Агент:

- идёт по задачам сверху вниз и отмечает исполненные;
- перед задачей со стоп-знаком останавливается и спрашивает вас;
- в конце проверяет беклог (`backlog verify`) и называет, что сделано и что осталось вам.

Если сеанс оборвался — запустите ту же команду: исполнение продолжится с первой
несделанной задачи.

Подробнее — [кейс 7](./docs/use-cases.md#кейс-7-исполнить-беклог-агентом)
и [кейс 8](./docs/use-cases.md#кейс-8-продолжить-прерванный-прогон).
