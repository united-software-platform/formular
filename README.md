## Что это

Беклог — носитель порядка работ одной операции и следа её исполнения. Он нужен операции,
у которой есть необратимый шаг либо шаг, выполнимый только владельцем: порядок, записанный
в беклоге, не теряется при обрыве, а каждая задача несёт проверку и признак «выполнено ранее»,
по которому исполненное распознаётся заново.

Система делает две вещи: порождает беклог по шаблону операции и несёт порядок, по которому
беклог исполняется. Исполняет его агент — по навыку `/backlog:backlog-run`.

Механизм поставляется плагином Claude Code: другой проект получает его установкой плагина,
а нормы и образцовый шаблон — прогоном `backlog install`. Репозиторий — первый потребитель
собственной поставки: его `rules/operation-backlog-rules.md`, `docs/glossary.md`,
`backlog/README.md` и `templates/sample-operation.md` установлены из неё, и слепки записаны
в [`.backlog-manifest.json`](./.backlog-manifest.json).

Нормы беклога — в [правилах](./rules/operation-backlog-rules.md) (`BKL-001`..`BKL-009`),
понятия — в [глоссарии](./docs/glossary.md).

## Состав

Поставка — каталог плагина [`plugin/backlog/`](./plugin/backlog):

| Что | Где в поставке |
|-----|----------------|
| Манифест плагина | [`.claude-plugin/plugin.json`](./plugin/backlog/.claude-plugin/plugin.json) |
| Вход командной строки | [`bin/backlog`](./plugin/backlog/bin/backlog) |
| Домен, сценарии и адаптеры | [`src/backlog/`](./plugin/backlog/src/backlog) |
| Сборка окружения | [`lib/python-env.sh`](./plugin/backlog/lib/python-env.sh) |
| Порядок исполнения | [`skills/backlog-run/`](./plugin/backlog/skills/backlog-run/SKILL.md) |
| Образцовый шаблон | [`templates/`](./plugin/backlog/templates) |
| Состав установки в проект | [`share/`](./plugin/backlog/share) |

Принадлежность репозитория, в поставку не входящая:

| Что | Где |
|-----|-----|
| Запись источника плагина | [`.claude-plugin/marketplace.json`](./.claude-plugin/marketplace.json) |
| Шаблоны операций проекта | [`templates/`](./templates) |
| Каталог следа — порождённые беклоги | [`backlog/`](./backlog/README.md) |
| Проверки ядра и установки | [`tests/`](./tests) |

Ядро обходится стандартной библиотекой: зависимостей у порождения нет.

## Установка в проект

Плагин ставится из перечня источников этого репозитория, нормы — прогоном установки:

```bash
claude plugin marketplace add united-software-platform/formular
claude plugin install backlog@formular
backlog install
```

Перечень источников добавляется однажды на профиль: запись в конфигурации проекта объявляет
его имя, но пригодным к установке не делает. Источником может быть и каталог репозитория
вместо адреса на GitHub — тогда механизм берётся из рабочего дерева, и правки в нём доезжают
до следующего сеанса без публикации.

`backlog install` кладёт в дерево проекта нормы, определения понятий, описание каталога следа
и образцовый шаблон, дописывает строки `@`-импортов в `CLAUDE.md` и пути в `.gitignore`
и пишет манифест установленного `.backlog-manifest.json` со слепком каждого файла.

Повторный прогон состояния не меняет. Файл, слепок которого разошёлся с манифестом, прогон
не перезаписывает: расхождение значит, что файл правил сам проект, — путь называется, прочие
файлы устанавливаются, а решение остаётся владельцу. Коды возврата: `0` — установка без
расхождений, `1` — расхождения названы, `2` — ошибка вызова или окружения.

Рабочие шаблоны операций проект пишет сам: образцовый шаблон показывает грамматику формата,
а состав задач у каждой операции свой.

## Запуск

Порождение беклога образцовой операции:

```bash
backlog generate --operation sample-operation \
  --value target=проба --flag host-part
```

- `--operation` — имя операции, оно же имя файла шаблона;
- `--subject` — предмет беклога; без него предметом становится штамп прогона `YYYYMMDDHHMMSS`;
- `--value ключ=значение` — значение подстановки шаблона, повторяется по значению; каждому
  значению заводится парная подстановка `ключ_scalar` в виде, пригодном для фронтматтера;
- `--flag имя` и `--no-flag имя` — признак условного блока, взведённый и снятый; признак,
  не названный вовсе, порождение останавливает;
- `--root` и `--templates` — каталог следа и каталог шаблонов; умолчания — каталоги `backlog`
  и `templates` в корне проекта либо значения переменных `BACKLOG_ROOT` и `BACKLOG_TEMPLATES`.
  Корень проекта вход находит сам, поэтому прогон из подкаталога второго каталога следа
  не заводит.

Коды возврата: `0` — беклог порождён либо уже лежал, `1` — ввод не позволяет его породить,
`2` — ошибка вызова или окружения. Состав вызова целиком — `backlog generate --help`.

Порождённый беклог не перезаписывается: повторный вызов над тем же адресом отвечает путём
лежащего файла и оставляет его неизменным.

## Разработка

Проверки ядра и установки — грамматика шаблона, маркер версии, вид значения фронтматтера,
запрет перезаписи, идемпотентность установки и обращение с правкой потребителя:

```bash
python3 -m unittest discover -s tests
```

Правила репозитория и точка их подключения в контекст агента — [`CLAUDE.md`](./CLAUDE.md).
Работа ведётся изменениями OpenSpec: предмет системы описан спецификацией
[`openspec/specs/backlog/operation-backlog/`](./openspec/specs/backlog/operation-backlog/spec.md).
