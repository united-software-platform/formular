# Design

## Context

Вход `backlog` имеет шесть подкоманд и текстовый вывод; парсер грамматики шаблона
`template_grammar()` уже существует в ядре (infrastructure) и возвращает подстановки и признаки,
но наружу его результат не выходит — он работает только внутри `check-template`. Навыки плагина
живут в `plugin/backlog/skills/<имя>/SKILL.md`; их два: приёмка шаблона и исполнение беклога.
Порядок работы в репозитории — Clean Architecture (сценарии использования в application,
детали в infrastructure), правила документации проекта требуют русской документации
с таблицей версий.

Дальше — фактическая сторона решений, принятых с владельцем на прожарке (Q1–Q11):
навык `backlog-generate`, после порождения один вопрос об исполнении, отказ при отсутствии
шаблона с отсылкой к приёмке, показ собранного вызова целиком, явный текст при занятом адресе,
интроспекция подкомандой поверх `template_grammar()`, текст по умолчанию с `--json`,
README переводит основной путь на навык.

## Goals / Non-Goals

**Goals:**

- Грамматика шаблона остаётся одним носителем — ядром: навык получает состав вызовом
  `inspect-template`, а не чтением шаблона глазами.
- Перечень выводимых порождением подстановок печатает вход, навык его не зашивает.
- Опыт владельца: от названной операции до порождённого беклога — один диалог без ручного
  открытия шаблона и ручной сборки вызова.

**Non-Goals:**

- Навык не пишет и не правит шаблоны, не правит беклоги, не исполняет их — границы соседних
  навыков и входа не сдвигаются.
- Интроспекция не проверяет структуру шаблона (это `check-template`) и не пишет файлы.
- Ручной вызов `backlog generate` не убирается и не deprецируется: он остаётся механизмом
  в кейсе 6 `docs/use-cases.md`.

## Decisions

### D1. Интроспекция — подкоманда, а не разбор глазами

`backlog inspect-template <путь>` поверх существующего `template_grammar()`: сценарий
использования в application (контракт «вход: путь → выход: три группы состава»), чтение файла
и разбор грамматики — infrastructure, печать — во входе. Альтернатива — навык, разбирающий
`{{...}}` глазами, — отвергнута на прожарке (Q7): второй носитель грамматики разошёлся бы
с ядром при первой правке, что противоречит BKL-008/BKL-010.

### D2. Состав вывода — три группы; `*_scalar` свёрнуты в ключ

Три группы: выводимые порождением сами (`date`, `run_stamp`, `operation`, `subject`, `runner`,
`template_version`), требующие `--value`, признаки. Парная `<ключ>_scalar` не занимает отдельного
места — она заводится входом от значения ключа (`__main__.py:170-187`), и вопрос о ней владельца
не видит. Перечень выводимых имён вход берёт из тех же констант ядра, из которых заполняет
подстановки `_derived_values` — не копией в новой константе: одна правка меняет оба места
разом. Альтернатива — отдельная константа перечня — отвергнута: две константы для одного
знания разошлись бы.

Пересечение групп: если имя, выводимое порождением, в шаблоне отсутствует — в вывод не
попадает; печатается только то, что есть в этом шаблоне.

### D3. Два формата: текст по умолчанию, `--json`

Текст консистентен с остальными пятью подкомандами; `--json` даёт строгий разбор навыку
и внешним скриптам. JSON-поля: `template_version`, `derived`, `values`, `flags`. Навык зовёт
с `--json`. Альтернатива «только JSON» отвергнута — первый и единственный JSON-выход во входе
выглядел бы чужеродно; «только текст» — потеря точности для машинного потребителя.

### D4. Навык — диалоговый сбор, порождение — входу

Порядок навыка: интроспекция → опрос значений/предмета/признаков (семантика предмета
показывается) → показ собранного вызова целиком → подтверждение → `backlog generate` → исходы
по таблице. Нормы называются кодом и вызовом `backlog norms --rule` (BKL-008), собственным
текстом — только порядок работы. Альтернатива «навык сам зовёт generate без подтверждения»
отвергнута (Q4): вызов, который пойдёт во вход, должен быть виден дословно до порождения.

### D5. README — основной путь на навык, кейс 6 — механизм

README несёт основной путь из четырёх шагов, и шаг порождения переводится на
`/backlog:backlog-generate`; ручной вызов остаётся в кейсе 6 `docs/use-cases.md` как документация
механизма для внешних систем и оболочек вне сеанса. Альтернатива «README не трогать» отвергнута
(Q8): README продолжал бы учить ручному сбору, закрыв глаза на навык.

### D6. Документация навыка — по образцу соседей

`SKILL.md` по канону соседних навыков: фронтматтер (name, description, allowed-tools
`Bash(backlog:*)`, Read), заголовок и назначение, навигация, границы навыка, порядок,
таблица исходов, версионирование DOC-022. Альтернатива «README навыка отдельным файлом»
отвергнута: у соседей один SKILL.md, второй файл — расхождение с каноном.

## Risks / Trade-offs

- [Перечень выводимых имён зависит от `_derived_values`] → источник перечня — те же константы,
  из которых заполняются подстановки; правка ядра меняет вывод интроспекции без отдельной
  правки (D2).
- [Навык читает JSON-вывод] → формат фиксирован спекой (поля `derived`, `values`, `flags`),
  текст — человекочитаемый дубликат тех же групп; расхождение форматов ловится приёмкой
  шаблона навыка прогоном на образце.
- [Два носителя поведения навыка: спека и SKILL.md] → спека хранит требования и сценарии,
  SKILL.md — порядок работы; границы прописаны в обеих одинаково (не пишет шаблоны, не правит
  беклоги, не исполняет).
- [Тексты справки входа на русском, JSON-поля латиницей] → нет конфликта: кодовые имена полей
  остаются английскими по DOC-002/DOC-003, проза — русской по DOC-001.

## Migration Plan

Изменение аддитивно: новая подкоманда, новый навык, правка README и кейсов. Отката не требует:
удаление подкоманды и навыка возвращает прежнее поведение; лежащие беклоги и шаблоны не
затрагиваются. Версия плагина поднимается правкой манифеста (см. plugin-delivery), норм
BKL-002 рекомендация о `.gitignore` печатается порождением как прежде.

Нет: состав решений закрыт прожаркой Q1–Q11, факты входа собраны разведкой кода.
