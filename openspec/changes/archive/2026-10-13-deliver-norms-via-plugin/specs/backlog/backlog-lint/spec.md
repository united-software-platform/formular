# Spec Delta

## MODIFIED Requirements

### Requirement: Предмет структурной проверки

Структурная проверка SHALL отвечать на вопрос, цела ли грамматика порождённого беклога,
и SHALL называть нарушением каждое из перечисленного:

- фронтматтер отсутствует, не разбирается либо не несёт версии шаблона, которой беклог
  порождён;
- в тексте осталась нераскрытая подстановка либо маркер условного блока;
- задача не несёт строки проверки либо строки признака «выполнено ранее»;
- фронтматтер не несёт указателя носителя порядка исполнения;
- файл не завершается таблицей версий;
- беклог не называет кодом какую-либо из норм исполнения — самодостаточность значений
  (`BKL-005`), признак исполнения (`BKL-006`), стоп-знак необратимой задачи (`BKL-007`),
  передача исполнения (`BKL-008`);
- первая задача беклога не называет носитель порядка исполнения значением указателя
  из фронтматтера;
- вторая задача беклога не называет прогон структурной проверки этого беклога.

Правила каркаса SHALL проверяться по смыслу — наличием кода нормы и названного в задаче
значения, — а NOT дословным совпадением текста с образцом и NOT адресом ссылки: дословное
правило ломалось бы при первой правке образца, а адрес нормы зависит от раскладки, которой
беклог не принадлежит.

Проверка SHALL читать только текст беклога и SHALL NOT обращаться к состоянию, которое беклог
исполняет: грамматика есть свойство файла.

Проверка SHALL называть каждое нарушение отдельно и SHALL NOT останавливаться на первом:
перечень целиком отвечает на вопрос, что в файле не так, одним прогоном.

#### Scenario: Задача без признака исполнения

- **WHEN** проверка прогнана по беклогу, где у задачи нет строки признака «выполнено ранее»
- **THEN** проверка называет задачу нарушением и возвращает код расхождений

#### Scenario: Нераскрытая подстановка в лежащем файле

- **WHEN** проверка прогнана по беклогу, в тексте которого осталась подстановка шаблона
- **THEN** проверка называет подстановку нарушением: порождённое правке не подлежит, и остаток
  подстановки означает либо дефект шаблона, либо правку файла руками

#### Scenario: Беклог цел

- **WHEN** проверка прогнана по беклогу, отвечающему всему перечню
- **THEN** проверка нарушений не называет и возвращает код чистого вердикта

#### Scenario: Беклог без задачи самопроверки

- **WHEN** проверка прогнана по беклогу, вторая задача которого не называет прогон
  структурной проверки
- **THEN** проверка называет нарушение каркаса и возвращает код расхождений

#### Scenario: Беклог без ссылки на норму исполнения

- **WHEN** проверка прогнана по беклогу, не называющему код нормы стоп-знака `BKL-007`
- **THEN** проверка называет отсутствующую норму нарушением

#### Scenario: Норма названа кодом без ссылки

- **WHEN** беклог называет нормы исполнения кодами и вызовом `backlog norms --rule`,
  без ссылок на файл норм
- **THEN** проверка нарушения каркаса не называет

#### Scenario: Норма названа кодом со ссылкой прежнего вида

- **WHEN** проверка прогнана по беклогу, порождённому прежде, где коды норм стоят текстом
  ссылок на файл норм в дереве проекта, и файла по ссылке нет
- **THEN** проверка нарушения каркаса не называет: коды в тексте есть, а адрес ссылки
  проверкой не сверяется

#### Scenario: Каркас иными словами

- **WHEN** беклог называет все нормы исполнения и обе первые задачи, но формулирует
  их иначе, чем образец
- **THEN** проверка нарушения каркаса не называет

#### Scenario: Беклог прежней версии шаблона

- **WHEN** проверка прогнана по беклогу, порождённому шаблоном без каркаса
- **THEN** проверка называет нарушения каркаса, а беклог задним числом не правится
