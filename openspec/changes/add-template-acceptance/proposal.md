# Proposal

## Why

Шаблон операции сейчас принимается только косвенно: `backlog generate` проверяет беклог,
порождённый при одном наборе значений и одном сочетании признаков, а вызывающему приходится
самому придумывать значения и перебирать признаки. Перенос восьми шаблонов в задаче FRM-010
показал оба пробела: прогон всех вариантов потребовал самодельного скрипта, а шаблон без
задачи самопроверки `backlog lint` и без ссылок на нормы исполнения структурную проверку
проходил. Шаблон должен уметь писать кто угодно — агент или внешний вызов, — поэтому
приёмка обязана быть прогоном, а не чтением глазами.

## What Changes

- Новая подкоманда `backlog check-template <путь к шаблону>`: прогоняет шаблон по всем
  сочетаниям признаков условных блоков на значениях-заглушках, без записи файла, и называет
  структурные расхождения каждого варианта. Коды возврата `0`/`1`/`2`.
- Структурная проверка беклога дополняется правилами каркаса: беклог ссылается на нормы
  BKL-005..BKL-008, первая задача первой группы называет носитель порядка исполнения, вторая —
  прогон `backlog lint`. Правила общие для `generate`, `check-template`, `lint` и `verify`.
  **BREAKING**: беклог, порождённый шаблоном без каркаса, `lint` и `verify` начинают отклонять;
  незавершённых беклогов такого рода в проекте нет, а расхождение на беклоге прежней версии
  шаблона README поставки уже допускает.
- Новый навык плагина `/backlog:backlog-template`: проверяет, нужен ли операции беклог
  (BKL-001), называет нормы ссылками и образец `templates/sample-operation.md`, принимает
  шаблон прогоном `check-template`. Шаблон пишет вызывающий; навык годится и для нового
  шаблона, и для правки существующего.
- Норма `BKL-009` переформулируется: изменение шаблона не считается завершённым без прогона
  `backlog check-template`. README каталога следа в поставке называет новую подкоманду.

## Capabilities

### New Capabilities

- `backlog/template-acceptance`: приёмка шаблона операции — подкоманда `check-template`
  (предмет, перебор признаков, значения-заглушки, вердикт) и навык `backlog-template`,
  ведущий вызывающего от критериев к принятому шаблону.

### Modified Capabilities

- `backlog/backlog-lint`: предмет структурной проверки пополняется правилами каркаса —
  ссылки на нормы исполнения и две обязательные первые задачи.
- `backlog/plugin-delivery`: состав плагина пополняется навыком приёмки шаблона.

## Impact

- Код плагина: `plugin/backlog/src/backlog/` — домен (`structure_findings`, поля
  `BacklogDocument`), разбор (`MarkdownBacklog`), новый сценарий приложения, подкоманда
  входа `__main__.py`, комментарий-шапка `bin/backlog`.
- Новый навык: `plugin/backlog/skills/backlog-template/SKILL.md`.
- Состав поставки: `plugin/backlog/share/rules/operation-backlog-rules.md` (`BKL-009`),
  `plugin/backlog/share/backlog/README.md`; доезжают в проект прогоном `backlog install`.
- Тесты: `tests/test_backlog.py`.
- Шаблоны `templates/` не меняются: все девять уже несут каркас и служат приёмочным набором.
