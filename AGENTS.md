## Понятия и нормы предмета

Определения понятий проекта живут в одном месте — в глоссарии поставки: правило отвечает
на вопрос «как положено», глоссарий — на вопрос «чем это является».

Оба документа подключаются в контекст агента из каталога поставки — `@`-импортом:

@plugin/backlog/share/docs/glossary.md

@plugin/backlog/share/rules/operation-backlog-rules.md

Копий норм и глоссария в дереве репозитория нет: источник — каталог поставки
[`plugin/backlog/share/`](./plugin/backlog/share), и правка в нём видна контексту репозитория
и навыкам плагина без установочного прогона.

Поставка `plugin/backlog/` от tessera не зависит и зависеть не должна: `backlog` — нижний слой,
tessera требует его, а не наоборот.

## Процесс разработки

Нормы git-процесса называются кодом правила из перечня tessera выше.

Шаблон имён рабочих веток проекта — `{CODE}-NNN-{краткое-описание}`, например
`FRM-005-rename-to-formular`: код проекта `FRM`, номер задачи и предмет работы. Имя `main`
остаётся защищённой базовой веткой по
[GIT-006](./.tessera/rules/git-rules.md#рабочая-ветка).

Служебные подписи об авторстве или генерации любых LLM-агентов и инструментов не добавляются
в сообщения коммитов и описания PR/MR — см.
[GIT-012](./.tessera/rules/git-rules.md#запрет-служебных-подписей).

Работа ведётся изменениями OpenSpec: порядок предложения, исполнения и архивации описан
в [`CONTRIBUTING.md`](./CONTRIBUTING.md#правила-и-процесс).

## Локальная настройка

Каталоги регистрации харнесов `.agents/` и `.zcode/`, как и локальная часть `.claude/` — ссылки
на навыки tessera и настройки харнеса, — находятся вне индекса git: их разработчик создаёт сам
под свои инструменты.

1. Навыки и правила tessera — из корня репозитория составом без formular: плагин `backlog`
   в этом репозитории свой, и поставка tessera его не дублирует.

   ```bash
   curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --scope project --components tessera,mattpocock-skills
   ```

   Ссылки на навыки ведут в хранилище машины и не коммитятся. Копии правил в `.tessera/rules/`
   и секция выше переносимы: они коммитятся вместе с проектом и обновляются повторным
   запуском. Состав до установки печатает та же команда с `--registry` рядом с теми же
   параметрами.

   > **Внимание:** состав у скрипта один на хранилище машины и ставится точно: запуск без
   > компонента снимает его клон вместе со ссылками других проектов на него, а `--uninstall`
   > снимает хранилище целиком.

2. Навыки OpenSpec. Для Claude Code инструментация в индексе — навыки `.claude/skills/openspec-*`
   и команды `.claude/commands/opsx/`. Для ZCode навыки подключаются ссылками
   `.zcode/skills/openspec-*` на них; команда — в [`CONTRIBUTING.md`](./CONTRIBUTING.md#локальная-настройка).
   Для прочего харнеса — `openspec init --tools <харнесы> --language ru --scope project`.
   Claude Code читает этот файл напрямую начиная с v2.1.277.

Плагин `backlog` в харнес разработки не подключается: беклог и есть этот репозиторий. Командную
строку вызывает прямо путь `plugin/backlog/bin/backlog`. Навыки `workflow-fast` и `workflow-grill`
в этом репозитории не работают: им нужен навык порождения плагина `backlog`.
